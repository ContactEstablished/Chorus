## §0 — Probe before you build (do not skip)

Three facts this spec rests on were measured on **2026-08-14**. Re-measure all three; **a task doc
built on a stale CLI fact wastes a session**, which is why CLAUDE.md forbids trusting recall for CLI
syntax.

```powershell
claude --version                                  # was 2.1.232
claude --help | Select-String "append-system-prompt"
claude --append-system-prompt-file                # expect: option '--append-system-prompt-file <file>' argument missing
codex --version                                   # was 0.147.0
```

**STOP and report** if `--append-system-prompt-file` is not accepted. The fallback is
`--append-system-prompt <text>` (inline argv), which is a **decision**, not a substitution: it puts
the whole snippet on a world-readable command line. Do not take it unilaterally.

**The fourth probe has no fallback and must be recorded either way** — codex's duplicate-key
behaviour:

```powershell
codex --strict-config -c developer_instructions="A" -c developer_instructions="B" debug prompt-input
```

Record which value survives into `_verify/6a-1/codex-duplicate-c.txt`. The implementation emits
**one** token regardless; the probe exists so the next person does not have to wonder.

## §1 — `src/main/adapters/instructionsCore.ts` (new, pure)

**Placement rationale:** it lives in `adapters/` beside `mcpConfigCore.ts` — the precedent for *a
pure core that adapters share so a rule does not get two homes* — and **not** in `services/`, because
its only consumers are adapters and the ipc composition. It must stay importable under plain node:
no `fs`, no `electron`, no `neo4j-driver`.

```ts
import { CHORUS_MEMORY_SERVER } from '../services/memoryService'
```

**⚠ THE SERVER NAME IS IMPORTED, NEVER RE-TYPED.** `memoryService.ts:160` already says renaming it
would strand the old entry in every `.mcp.json` Chorus has written; a second spelling here would
teach agents a name the config does not use. (The import is type-free and cheap —
`memoryService.ts` imports no Electron.)

### The contract text

One exported array of sentences, rendered two ways. **Each element is one physical line and contains
no newline** — that is what makes the codex render legal.

```ts
export function memoryContractLines(): readonly string[] {
  return [
    `This project has a memory graph, reachable through the "${CHORUS_MEMORY_SERVER}" MCP server (Neo4j, queried with Cypher).`,
    'READ BEFORE ASSUMING: before re-deriving how this project is arranged, or re-discovering a decision, query the graph. Structural nodes (:File, :Directory, :Commit) record where code lives; :Memory nodes record decisions, observations and risks.',
    'WRITE AFTER A MILESTONE, not after every turn: a decision taken, a durable observation, or a risk found — never a running commentary, and never something you have not verified.',
    'EVERY MEMORY MUST CITE ITS SOURCE: attach SUPPORTED_BY to the :File or :Commit it is about, and PRODUCED from your own :AgentSession node. An uncited memory is counted as unsourced and lowers this project’s provenance ratio.',
    'NEVER DELETE OR RELABEL A MEMORY YOU DID NOT WRITE. Supersede instead: set validTo on the old node and create the new one.',
    'Structural nodes are machine-generated by Chorus and are refreshed wholesale; do not hand-edit them.',
    'The graph is scoped to this project. Do not assume it holds anything about another repository.'
  ]
}
```

**Why these seven and not more.** Every line is paid for on every launch, in context. Each one either
prevents a wrong action (writing without a source, deleting someone else's memory, editing generated
nodes) or enables a right one (query first). The provenance line exists because
`memory:validate`'s denominator is otherwise measuring an instruction nobody was given (identity
model §6, D126 item 4).

**Note the two Unicode escapes.** The apostrophe is written `’` deliberately: a straight quote
inside a TOML basic string is legal, but the file is also read by a human and the codebase's own
prose uses typographic quotes. Do not "simplify" it into an unescaped `'` inside a single-quoted TS
literal.

### The two renderers

```ts
/** claude's file: Markdown, headed, trailing newline. */
export function renderInstructionsMarkdown(lines: readonly string[]): string {
  return ['# Project memory (Chorus)', '', ...lines.map((l) => `- ${l}`), ''].join('\n')
}

/** codex's argv: ONE physical line. */
export function renderInstructionsOneLine(lines: readonly string[]): string {
  return assertSingleLine(lines.join(' '))
}

/** ⚠ LOAD-BEARING, NOT DEFENSIVE. `tomlBasicString` (mcpConfigCore.ts:40) escapes
 *  backslashes and quotes and NOT newlines, so a raw newline reaching a
 *  `-c key="…"` override is an illegal TOML basic string — and codex reports an
 *  unknown or malformed `-c` path by IGNORING IT SILENTLY (codex.ts:680). The
 *  symptom would be a contract that simply never arrives. */
export function assertSingleLine(v: string): string {
  if (/[\r\n]/.test(v)) throw new Error('A codex developer instruction must be one physical line.')
  return v
}
```

## §2 — `src/main/adapters/types.ts`

**Insertion points, in file order.**

1. **After `AgentCapabilities.hooks` (`:55`)** — one field, **required and nullable**, exactly like
   its three siblings, so every adapter is forced to answer:

```ts
  readonly instructions: InstructionsDescriptor | null
```

2. **Beside `HooksDescriptor` (`:175`)**:

```ts
/**
 * How an adapter is given session-level instructions (D148).
 *
 * ⚠ `append-system-prompt-file` WRITES A CHORUS-OWNED FILE AND `config-override`
 * WRITES NOTHING AT ALL. Neither touches a file the user authored — that is the
 * whole point of the capability, and D49 is why it exists in this shape rather
 * than as a `CLAUDE.md` writer.
 */
export interface InstructionsDescriptor {
  readonly mode: DescriptorMode
  readonly mechanism: 'append-system-prompt-file' | 'config-override'
}
```

3. **Beside `PtyLaunchHooks` (`:402`)** — the same main-owns-policy / adapter-owns-format split, and
   the docblock should say so by naming `PtyLaunchHooks` as its precedent:

```ts
export interface PtyLaunchInstructions {
  /** The contract text main composed. NON-SECRET BY CONSTRUCTION: a static
   *  string plus a server name; no user input reaches it. */
  readonly text: string
  /** Absolute path main reserved for an adapter that needs a file. Main creates
   *  the parent directory and deletes the file at session end; the adapter only
   *  writes. Ignored by a `config-override` adapter. */
  readonly filePath: string
}
```

4. **On `PtyLaunchSpec`, after `hooks` (`:367`)**:

```ts
  /** D148: the memory usage contract for THIS launch. Absent whenever the
   *  project has no memory configured — which is most launches — and argv must
   *  then be byte-identical to HEAD. */
  readonly instructions?: PtyLaunchInstructions
```

5. **Beside `SupportsMcp` / `supportsMcp` (`:776`)**:

```ts
export interface SupportsInstructions {
  /** Returns the argv tokens, writing a file first if this adapter's mechanism
   *  needs one. `null` means "no contract for this launch" and MUST yield `[]`
   *  for a file adapter — but codex still returns its own baseline instruction,
   *  which is why the parameter is nullable rather than the method optional. */
  instructionsArgs(instructions: PtyLaunchInstructions | null): readonly string[]
}

export function supportsInstructions(
  a: BaseAgentAdapter
): a is BaseAgentAdapter & SupportsInstructions {
  return (
    a.getCapabilities().instructions !== null &&
    typeof (a as Partial<SupportsInstructions>).instructionsArgs === 'function'
  )
}
```

    if (!instructions) return []

      fs.mkdirSync(path.dirname(instructions.filePath), { recursive: true })
      fs.writeFileSync(instructions.filePath, instructions.text, 'utf8')

## §4 — `src/main/adapters/codex.ts`

**⚠ THIS IS THE DELICATE ONE.** `developer_instructions` is already emitted from
`CODEX_BASELINE_ARGS` (`:742`). After this change it must have **exactly one emitter**.

**Capability (`:105`, replacing nothing, added after `hooks: null`)**

```ts
      instructions: { mode: 'static', mechanism: 'config-override' }
```

**`CODEX_BASELINE_ARGS` loses its second pair:**

```ts
export const CODEX_BASELINE_ARGS: readonly string[] = [
  '-c',
  `tui.status_line=${tomlStringArray(CODEX_STATUS_LINE)}`
]
```

and its docblock gains a line saying **where the developer-instructions pair went and why** — the
existing docblock explicitly exists so *"any unreviewed token appearing here still fails the pin"*,
and a reader who finds the pair missing must be told it moved rather than left.

**The method:**

```ts
  /**
   * ⚠ THE ONE HOME OF THE `developer_instructions` TOKEN. `-c` REPLACES rather
   * than appends (see CODEX_JADE_ECHO_INSTRUCTIONS above), so a second token
   * would silently destroy one of the two values — and codex ignores a
   * duplicated or unknown `-c` path WITHOUT A WORD. Both parts are therefore
   * composed into one value here, and nothing else in this file may emit that
   * key.
   */
  instructionsArgs(instructions: PtyLaunchInstructions | null): readonly string[] {
    const parts = instructions ? [CODEX_JADE_ECHO_INSTRUCTIONS, instructions.text] : [CODEX_JADE_ECHO_INSTRUCTIONS]
    return ['-c', `developer_instructions=${tomlBasicString(assertSingleLine(parts.join(' ')))}`]
  },
```

**`buildLaunch` (`:142`)** — called unconditionally, in the position the pair occupies today:

```ts
    const args = [...cli.args, ...CODEX_BASELINE_ARGS, ...this.instructionsArgs(spec.instructions ?? null)]
```

**⚠ BYTE-IDENTITY IS THE ACCEPTANCE TEST HERE, NOT AN ASPIRATION.** With `spec.instructions`
absent, this expression must produce exactly what `[...cli.args, ...CODEX_BASELINE_ARGS]` produced
before — same tokens, same order. Pin it with an exact-equality assertion built from
`resolveCli(id).args` plus the two literal pairs, as the existing suite already does.

### Runtime — the part that decides the task

1. **Before**: hash `~/.codex/config.toml` (`Get-FileHash`), **re-baselined immediately before the
   launch** — codex writes that file itself, and a four-day-old hash reports a change Chorus did not
   make (the Phase 6 G2 lesson, learned the hard way).
2. Launch a **claude** pane in a memory-configured project. Then:

```powershell
Get-CimInstance Win32_Process | Where-Object CommandLine -like '*claude*' | Select-Object -Expand CommandLine
Get-ChildItem "$env:APPDATA\chorus-app\agent-instructions"   # or the dev userData path
```

   Expect `--append-system-prompt-file <path>` and a readable Markdown file at that path.
3. **The rehearsal for the phase milestone:** in that pane, ask *"what memory do you have available
   for this project?"* — **without naming `chorus-memory`** — and save the transcript. An agent that
   names the server has read the contract.
4. Close the pane. `Get-ChildItem` the directory again: **the file is gone.**
5. Launch a **codex** pane in the same project. Confirm from the live command line:
   **exactly one** `-c developer_instructions=` token, containing both the jade rule and the memory
   contract, on one line. Confirm the jade block still renders in its first reply — **this is how you
   know the composition did not eat the formatting rule.**
6. Launch both agents in a project with **no** memory configured. Confirm **no** instructions token
   for either, and that codex's argv matches the pre-task capture byte for byte.
7. Re-hash `~/.codex/config.toml`: **byte-identical.**

Save everything under `_verify/6a-1/`.

### The invariant a reviewer should test hardest

**A launch with no memory configured must be byte-identical to HEAD for all four PTY adapters.** Not
"equivalent", not "the same tokens in a different order" — identical. Capture the command line before
the change and after it and diff the two files. Every argv regression this project has shipped was
invisible to the person who made it and obvious in a diff.
