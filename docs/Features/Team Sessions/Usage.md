# Using Team Sessions

The September 30 dependability update is implemented in the working tree. It adds an Opus lead preset, two independent DeepSeek Flash helper slots, recorded project checks, and controlled publication and cleanup. An already installed release does not acquire these changes until rebuilt and installed. See [compatibility evidence](Compatibility-Report.md) and [evaluation evidence](Evaluation-Report.md).

Open a project's launch dialog and choose **Team session**. Select one lead and at least one helper. The lead owns the terminal you interact with; helpers execute delegated tasks in isolated worktrees. Multiple roster entries can use the same available model. **Concurrent helpers** controls how many may execute at once, independently of roster size.

The new default is Claude Opus 5.5 with explicit medium effort and two OpenCode/OpenRouter DeepSeek V4.1 Flash helpers using a selected saved API credential. Each slot has its own task and worktree identity; the slots may share the same model and credential. Claude/Sonnet, Codex/gpt-6-astra and saved custom OpenRouter helper profiles remain available. **Launch diagnostics** distinguishes historical verified combinations from compatibility pilots and reports exact CLI versions. Subscription models use the account already signed into that CLI. Opus is currently a lead option.

With Codex CLI **0.159.0**, choose **Codex · gpt-6-astra** or **Codex · gpt-6.1-sol** as lead and select DeepSeek V4.1 Flash in both helper slots. Set concurrent helpers to two. New GPT lead selections use medium effort; Codex uses standard context. Its Team server receives a scoped long-wait timeout and the lead uses an isolated native process. Sol is a lead option only. Native runtime pilots pass for both leads, but the current build's packaged task checks and longer performance comparison remain blocked by missing test executables; consult the current [compatibility status](Compatibility-Report.md) before treating it as a qualified packaged release.

For the current Claude pilot, **Lead context → Team tools and project memory** loads the Team bridge and configured project memory while disabling unrelated CLI skills and MCP servers. CLI permissions, settings and hooks still apply. Choose **Include configured CLI skills and servers** when the task needs those integrations. Existing presets retain their previous context. This option limits loaded integrations; the recorded pilots do not demonstrate lower lead token use.

Choose a committed base, helper timeout, project checks and finish policy:

- **npm tests, typecheck and build** requires committed `package.json`, `package-lock.json`, and `test`, `typecheck` and `build` scripts. Chorus runs `npm ci` in each isolated workspace and refreshes dependencies when package metadata, the lockfile, or `.npmrc` changes, or an installation fails. Helpers may invoke only the exact standalone commands `npm test`, `npm run typecheck`, `npm run build`, and `node --test`. Arguments, redirects, compound commands and arbitrary scripts are denied. Project scripts may internally contain the commands needed for that project.
- **Node tests only** uses the exact `node --test` command.
- **Merge into the current branch when clean, then clean up** records the destination checkout, branch and HEAD at launch. After accepted reviews and actual checks, Chorus fast-forwards that same clean, unchanged destination to the exact verified result. A dirty checkout, changed branch/HEAD, conflict or unknown process state blocks the effect and retains evidence. It does not push.
- **Keep verified output on the Team branch** completes the session with its worktrees retained. Old presets and serialized sessions retain this behavior; they do not gain automatic publication silently.

Choose **Launch team**, finish any native CLI trust prompt, and describe the task in the lead terminal. For example: “Use the helpers to implement these two independent changes, review their results, and run the integrated tests.” Expand **Team** to inspect task status, attempts, helper activity, reviews and pending decisions. Corrections go to the lead terminal. Helpers are read-only views; they do not get separate interactive panes.

The lead reviews artifacts and prepared changes automatically. No Team approval button is needed. Native CLI workspace trust and unrelated command permissions remain separate.

Give each code helper a concise assignment, explicit writable paths, acceptance criteria and committed reference paths. Put detailed requirements in committed specifications/tests; reference their sections rather than copying them. Chorus supplies the supported command and capture rules. Chorus preflights references and checks before reserving an attempt, and rejects captured changes outside explicit ownership. Helpers cannot see the lead conversation or uncommitted files in another worktree. A permission denial is retained as an unsuccessful attempt and requires a counted revision; it does not open a hidden helper approval prompt. At most three attempts are available per task.

The lead uses compact `team_status`/`team_wait` responses and an actionable cursor. Decision waits (`target: "results"`, with outstanding task IDs and `afterSequence`) suppress preparation and live-output chatter. For tested Claude 2.1.285/2.1.286 leads, a wait can span up to 15 minutes inside one model tool call, using bounded authenticated broker segments. Cancellation and lease revocation still terminate the wait. `team_detail` provides paginated task evidence/diffs. `team_verify` with `command: "suite"` queues all configured checks at an exact clean integration SHA and returns `verificationIds`. Use `team_wait` with `target: "checks"` and those IDs, then pass `verificationIds` into integrated reviews. Chorus resolves and validates the original evidence; the lead need not copy logs. `team_detail` with `section: "checks"` remains available when full output is needed. Helper prose cannot substitute for that execution. Use `team_delegate_many` for independent assignments and `team_review_many` for same-phase reviews. Each item retains its own request ID and review history; invalid batches do not partially apply. Prepare and apply code integrations serially against exact HEADs. After all reviews complete, `team_finish` performs remaining checks and the selected finish policy. The Team panel reports cleanup after retiring the lead; avoid repeated finish polling.

**Pause** revokes new dispatch and drains owned work before reaching paused state. **Resume** explicitly authorizes continuation. After an application restart, retained Teams stay paused; they do not launch agents automatically. If retained dirty work blocks Resume, **Recover retained work** provides a lead for resolving it with helper dispatch and integration disabled.

Closing the pane detaches the view. Reopen it through **Existing teams → Open lead**. **Stop** retains worktrees and history. **Finish team** requests verified completion. The panel reports publication and removed/retained worktree counts. Cleanup deletes only owned worktrees with proven stopped writers and preserved immutable content. Failed attempts, unknown ignored files, additional edits and ambiguous identities are retained with reasons. **Retry cleanup** rechecks eligible retained workspaces after publication. Final private Git refs and history survive cleanup. Published/cleaned sessions are archives; start a new Team to continue from their result.

On restart, Chorus retires journaled verification processes and reconciles publication identities without replaying commands, merging or deleting. An interrupted publication that already reached the exact result is recorded as published; cleanup requires an explicit retry.

Project checks retire positively identified background writers, including native compiler services, after the command exits. Unknown process ownership blocks further checks, integration, publication and cleanup. Cleanup removes nested dependency links without traversing their targets, preserving tracked source and external directories.

Use **Reusable team presets** to save a roster and launch settings. Reported token usage may be incomplete, and subscription expenditure is unknown. The [recorded comparisons](Evaluation-Report.md) show high overhead for small tasks and encouraging lead-token reduction on a ten-minute fixture. The larger single pair required permission retries and an overlap-accounting correction; actual subscription expenditure and dependable average speedup remain unknown.

The development comparison command is `node scripts/benchmark-team-dependability.mjs --repetitions 3`. It runs Opus alone, Opus with one helper, and Opus with two helpers sequentially on small and substantial disposable fixtures, rotating condition order. Source and acceptance checks are frozen, and failures remain recorded. It reads the existing credential profile without modifying it and requires native Claude, OpenCode and Node. Reports go to a new temporary evidence directory. Helper CLI cost reports are not reconciled bills; subscription dollars remain unknown.

For the larger eight-module comparison, use `node scripts/benchmark-team-dependability.mjs --workload long --conditions lead-only,team-2 --repetitions 1`. Each run has a 15-minute limit; actual duration depends on model performance. The recorded follow-up took 3:24 solo and 6:38 with two helpers and did not show savings.

The larger follow-up command is `node scripts/benchmark-team-dependability.mjs --workload extended --conditions lead-only,team-2 --repetitions 1 --context focused`. It uses twenty modules, frozen specifications and acceptance tests, and the same 15-minute submission limit for both conditions. Calibrate the contract before freezing the measured pair; keep calibration separate from comparison results.

Helpers must use native read/glob/grep for discovery. Shell directory listings (`Get-ChildItem`, `ls`, `dir`, `pwd`) are denied; only listed standalone verification commands are permitted. A failed attempt remains retained for inspection. Cleanup retries use the same owned-process and content checks; unknown live process identity blocks deletion.
