## Demonstrated causes and changes

1. **Revision continuity:** The real Git/Storage/TeamWorkspaceService reproduction failed before the fix: a one-line correction began with both owned files reverted to stubs. Attempts now reserve explicit provenance from the last successful captured artifact. A fresh workspace applies that artifact onto the reserved integration baseline; the original baseline remains the capture parent, so the complete deliverable survives integration. Scope, artifact ref identity, stopped writers and ancestry are checked. Conflicts retain work and fail preparation. Failed partial files never become seeds. Seed effects are journaled; recovery does not replay them.
2. **Windows environment casing:** Spreading `process.env` removes its Windows case-insensitive lookup. The allowlist looked up `PATH`, while the parent supplied `Path`, so Team leads lost it. Canonical allowlisted names now use case-insensitive lookup. Credential isolation stays in place. Native PowerShell still found Node before the fix; this does not establish the cause of the earlier optional Node reader failure. Codex instructions explicitly permit read-only fallback through `Get-Content` or `rg`.
3. **Generation exhaustion:** The three historical native OpenCode records identified by the plan all report `length`, including the two previously inferred only from counters. A native OpenCode 1.18.33 loopback probe, with no real credentials or provider traffic, shows default DeepSeek requests use `max_tokens: 32000` and omit reasoning effort. The `low` variant serializes `reasoning: {effort: "low"}` but still exhausted 32,000 reasoning tokens on a ten-file assignment. A bounded native 64,000-token diagnostic completed all 131 original data tests; its first implementation step needed 41,822 reasoning tokens before useful output. New helper selections now default to low for this exact model/version. Code dispatch sets the measured `OPENCODE_EXPERIMENTAL_OUTPUT_TOKEN_MAX=64000` only for OpenCode 1.18.33, DeepSeek V4.1 Flash and low effort. Ambient overrides are rejected, other model/version/effort combinations keep their previous behavior, and stored runs are not rewritten. The setting also affects the native client's automatic title request. A larger maximum can permit more usage; it is not a cost-saving claim. Structured result evidence distinguishes generation truncation, provider error and other unsuccessful finishes. Usage remains separate and retains record identity.
4. **Recovery instructions:** Leads now distinguish correcting a bad path/unsupported command from repeating a denial unchanged, retain independent valid work, and use counted revisions within the three-attempt ceiling. Content review remains tied to committed requirements. Helpers receive the authoritative workspace and explicit guidance against Git/version probes and external scratch paths. Revisions also receive the immutable original assignment alongside the current correction; the Sol recovery control exposed the loss of the original ASCII requirement in a short revision brief. Preparation errors retain their specific sanitized cause.
5. **Local feedback:** The separately flagged `--local-checks` fixture supplies a committed `npm test` runner that selects the application's declared helper ownership. The extended suite is partitioned into 131 data and 63 job tests with no gaps or duplicates. The original acceptance files remain byte-identical, and independent combined acceptance runs all 194. This is a new condition, not a replacement for historical measurements.
6. **Verifier reliability:** The pilot records sanitized actual PTY launch settings and compiled-bundle/bridge identity. Codex's visibly pending paste receives one guarded Enter retry. This only submits an unsent prompt. Native denied calls count even when the final attempt status is cancelled. The benchmark stops on failure, preserves reports and marks incomplete trial coverage invalid.
7. **Native file-path contradiction:** In the first extended budget trial, a helper attempted forbidden shell discovery, then its counted retry mistyped the absolute worktree prefix. Native records distinguish both from missing write authority. A deterministic loopback probe showed OpenCode's tool descriptions demand absolute paths while actual native read/write/edit/glob/grep accept relative paths correctly. The measured helper route now pins the build agent and supplies a system prompt explaining this verified relative-path behavior and exact shell allowlist. Native delivery and all five tools passed; permissions stay unchanged. Live qualification of that prompt is recorded separately.
